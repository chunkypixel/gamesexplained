Commodore 64 · 1987 · Electronic Arts

Skate or Die!

What High Jump's code does that the manual does not say: rules that cost a skater height, code nothing calls, and what earlier parts of the game left behind in memory.

01 · Rules the manual leaves out

The last pass is the one that counts

  • A better pass is thrown away. The manual says the skater gets up to five passes and should press fire at the top of a jump to record it.1 It does not say that each pass wipes the one before: the height is cleared each time a new pass begins ($1798), so a skater who reaches 12 feet on the second pass, does not press fire, and manages 9 on the fifth leaves with 9. In an emulator, three passes recorded 47, 75 and 95 eighths of a foot, each cleared as the next began.
  • Too high counts as nothing. A height of 150 eighths, 18 feet 9 inches, or more is recorded as zero ($1ABC). The test is there to throw out positions below the coping, where the subtraction wraps round; a jump that high would fall foul of it too. No pass in testing came near.
  • The crowd is watching. After every turn on the right wall, half that pass's height sets how often a head in the stands moves ($1AD0, $19AE): the higher the jump, the livelier the crowd.
  • Free speed at the end. Once the attempt is over, the pumping routine restarts its burst of speed every frame, with no input at all ($16E3), which carries the skater back to the platform.
  • The keyboard is a joystick. One row of keys shares its wires with joystick 1, and the game reads both, so SPACE fires and 1, the left arrow, CTRL and 2 steer ($0D23).

02 · The same tune, until it isn't

The music's dice are loaded from disk

The music picks its phrases at random, from a byte at $35AB that the random routine shifts each time it is used ($357E). Nothing in High Jump ever sets that byte: its value arrives with the event's code from the disk. So the first time the music plays after the event loads, it always takes the same phrases in the same order. Turning the sound off and on, or practising again without a reload, carries on from wherever the byte has got to, and the order changes. The Music tab plays that first order.

03 · Practice again

A jump that erases itself

The event's first instruction, at $0880, jumps to the code that loads its four files from disk. When that is done, the code writes three NOP instructions over the jump ($0893), so that the next time anything jumps to $0880 it falls through to the start of a new attempt instead. PRACTICE AGAIN? jumps to $0880 ($F93E), and a second attempt starts at once, without the drive.

04 · Code nothing calls

Left in from development

  • Zoom by joystick. A routine moves the scale the game uses to place the ramp on screen up and down with the joystick ($1743). Nothing calls it.
  • A height counter in a sprite. Another draws the height into the ruler's sprite ($155C); the event shows the height in the status line instead.
  • A pause that cannot resume. The sound driver has routines to stop, pause and resume a sound ($2303, $2319, $2321). The pause overwrites all of a voice's flags, so the resume finds nothing to restart. High Jump uses none of them; the driver looks shared with other parts of the game.
  • Sounds High Jump never plays. Of the 26 sound numbers loaded with the event, High Jump's code asks for eight and the music asks for one more, its second voice. Of the other 17, three point at a script that ends at once; the rest are full sounds nothing in this event asks for.
  • A lucky read. One table lookup ($1166) is indexed by a value that is $FF just after the skater crosses the middle, which reads a byte of the ramp table instead. It works because that byte is not zero.

05 · What earlier loads left

Memory is never cleared between events

Each event loads over the last, and what it does not overwrite stays. In High Jump, the screen for the shop's records is still in memory behind the event's font ($6A00), a copy of the part of the game that runs between events sits after the skater's sprite shapes ($C2B0), and the KERNAL's tape messages, PRESS PLAY ON TAPE among them, survive from a copy of the operating system ($F0D9). The interrupt vector for the RESTORE key still points where an earlier load put it, into the middle of a High Jump routine ($0A3A).

The game's own disk code stays resident the whole time ($F230). It has no directory: files are numbered, 49 of them, and found by track and sector from a table ($F2F9). Before each file it tells the drive to expect the disk ID "EA", and it reads three bytes from track 18, sector 18 that say which side is in the drive: three 1s on side 1, three 2s on side 2 ($FA69). The wrong side brings up INSERT SIDE 1 AND PRESS BUTTON.
